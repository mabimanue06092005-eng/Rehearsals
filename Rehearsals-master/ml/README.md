# Turn-state classifier — status

**Integrated and live.** The app classifies each user turn (comfortable /
hesitant / defensive / shutdown) with a client-side TF-IDF + multinomial
logistic regression model — see the generated block between
`// -- BEGIN local turn classifier (generated by ml/inject_model.py) --` and
`// -- END local turn classifier --` in `index.html`, right before
`classifyUserTurn()`. No network call, no per-turn API cost; the old LLM
prompt call for this specific purpose is gone (the richer end-of-session
debrief still uses the real LLM — see `functions/api/debrief.js`).

Pipeline: `generate_data.py` bootstraps a synthetic labeled dataset
(documented as synthetic throughout, never passed off as real user data) →
`train.py` trains a TF-IDF + logistic regression model on it and writes
`ml/data/model.json` + `ml/data/eval_report.txt` → `inject_model.py` splices
that model and its inference code into `index.html`. Currently at 88.5%
held-out accuracy on 480 synthetic examples (`ml/data/eval_report.txt`).
Prosody (pause ratio, volume, volatility) is fused in afterward via a
documented rule in `applyProsodyAdjustment`, not jointly trained.

**Important caveat this status note previously obscured:** the model
driving real users' whisper-coach nudges right now is trained entirely on
synthetic, LLM-generated examples — not real conversational data. It has
never been validated against how an actual person types when hesitant,
defensive, or shutting down. Treat its current accuracy number as a
sanity check on the pipeline, not a claim about real-world quality.

**Next step, once the pilot study (see `../pilot/`) has produced real
transcripts:** relabel/retrain on real data and re-run `inject_model.py`.
That's the actual blocker to improving this — not the code, which already
works end-to-end (`generate_data.py` → `train.py` → `inject_model.py`).
